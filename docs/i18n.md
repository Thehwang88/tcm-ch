## 2. Translation workflow (no auto-publish)

Two separate axes per entry. **Editorial** (`editorial`): `Missing` → `Draft` → `Needs clinical review` → `Approved`; `Outdated` is computed by the gate (DE source hash ≠ captured hash), never hand-set. **Publication** (`publication`): `Unpublished` | `Published` = whether the EN URL is live on production. Editorial approval never deploys anything; a release commit flips `publication`.

1. German page changes → `node scripts/check-i18n.mjs` warns `Outdated` for every EN entry whose `sources` changed (`--strict` fails; used in release checks).
2. Editor updates the EN copy → sets `editorial` (`Draft`, or `Needs clinical review` when `clinical: true`).
3. Review → `Approved`. Only `Approved` entries are hreflang- and sitemap-eligible. `Missing` entries must not build; `Draft`/`Needs clinical review` build locally with a WARN (`--strict`: FAIL) and must not reach `main`. A `Published` entry whose copy is not `Approved` fails the gate.
4. Release GO → `publication: 'Published'` for newly deployed URLs + `node scripts/check-i18n.mjs --update` in the same commit (captures the reviewed DE state).

New EN page checklist: registry entry (id, de/en, sources, images, links) → page under `src/pages/en/` with `Layout` (`path`, `title`, `description`, `schema`) → DE twin declares the EN alternate (automatic via `PAIR_MAP`) → `seo/index-queue.md` entry in the same commit → gates.
