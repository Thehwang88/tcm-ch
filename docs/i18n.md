URL doctrine: EN routes stay `/en/…` (51 live, indexed URLs preserved, no redirects). German keyword ownership is untouched: EN pages are `language_twin` rows in `seo/master-keyword-url-map.csv` and never target DE head terms.

## 2. Translation workflow (no auto-publish)

Statuses (`TranslationStatus`): `Missing` → `Draft` → `Needs clinical review` → `Approved` → `Published`. `Outdated` is computed by the gate (DE source hash ≠ captured hash), never hand-set.

1. German page changes → `node scripts/check-i18n.mjs` warns `Outdated` for every EN entry whose `sources` changed (`--strict` makes it fail; use in release checks).
2. Editor updates the EN copy → sets the entry status (`Draft`, or `Needs clinical review` when `clinical: true`).
3. Review → `Approved`. Only `Approved`/`Published` entries are hreflang- and sitemap-eligible. `Missing` entries must not build; `Draft`/`Needs clinical review` build locally with a WARN and must not reach `main`.
4. Release GO → status `Published` + `node scripts/check-i18n.mjs --update` in the same commit (captures the reviewed DE state).

New EN page checklist: registry entry (id, de/en, sources, images, links) → page under `src/pages/en/` with `Layout` (`path`, `title`, `description`, `schema`) → DE twin declares the EN alternate (automatic via `PAIR_MAP`) → `seo/index-queue.md` entry in the same commit → gates.
